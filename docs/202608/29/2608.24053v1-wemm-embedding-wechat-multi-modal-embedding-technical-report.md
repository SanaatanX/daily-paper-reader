## 摘要
通用多模态嵌入正成为现代AI系统的核心组件，使异构内容能够在共享空间中表示，用于检索、推荐、分类和智能体系统等应用。在本报告中，我们介绍了WeMM-Embedding，一个通用多模态嵌入模型系列，支持文本、图像、视频、视觉文档以及任意交错的多模态输入，并具有灵活的输出维度。该系列包含2B、4B和9B三种规模变体，并采用两阶段训练：大规模多模态对齐阶段，以及使用精选数据、细粒度相关性监督和跨尺度知识迁移的微调阶段。在广泛的评估中，WeMM-Embedding在多个公共基准上取得了领先性能。值得注意的是，2B变体在MMEB-v2上已经超越了此前领先的8B开源基线，而9B变体进一步取得了80.6的新最先进总体分数。WeMM-Embedding还在微信应用中展示了强大的实际性能，在26任务内部基准上取得了显著提升，并在14项在线A/B测试中持续改进。它已大规模部署于推荐和搜索应用中，包括微信视频号、公众号、朋友圈和电商服务。我们已发布模型权重和代码，以促进未来研究，参见https://github.com/Tencent/WeMM-Embedding。

## Abstract
Universal multimodal embeddings are becoming a core component of modern AI systems, enabling heterogeneous content to be represented in a shared space for applications such as retrieval, recommendation, classification, and agentic systems. In this report, we present WeMM-Embedding, a family of universal multimodal embedding models supporting text, images, videos, visual documents, and arbitrarily interleaved multimodal inputs with flexible output dimensions. The family comprises 2B, 4B, and 9B variants and is trained in two stages: a large-scale multimodal alignment stage, followed by a refinement stage using curated data, fine-grained relevance supervision, and cross-scale knowledge transfer. Across extensive evaluations, WeMM-Embedding achieves leading performance on multiple public benchmarks. Notably, the 2B variant already surpasses the previously leading 8B open-source baseline on MMEB-v2, while the 9B variant further achieves a new state-of-the-art overall score of 80.6. WeMM-Embedding also demonstrates strong practical performance across WeChat applications, with substantial gains on a 26-task in-house benchmark and consistent improvements across 14 online A/B tests. It has been deployed at scale across recommendation and search applications, including WeChat Channels, Official Accounts, Moments, and e-commerce services. We have released the model weights and code to facilitate future research at https://github.com/Tencent/WeMM-Embedding.

# WeMM-Embedding：微信多模态嵌入技术报告 — 中文总结

## 一、核心问题与研究动机

- **背景与问题**：通用多模态嵌入已成为检索、推荐、分类和智能体系统的核心组件，需要将文本、图像、视频等异构内容映射到统一表示空间。早期 CLIP 风格双编码器无法处理交错多模态输入（如图文文档、组合查询、带转写文本的视频）；后续基于视觉编码器的方法在扩展性和泛化性上仍受限。
- **核心思路**：基于多模态大语言模型（MLLM）构建通用多模态嵌入模型，使其天然支持任意交错输入的联合表示，并保持强大的预训练能力。
- **目标**：提出 WeMM-Embedding 模型家族（2B / 4B / 9B），通过“大规模对齐 + 精炼”的两阶段训练，在保留广泛能力覆盖的同时不断优化相关性建模，最终在公共基准和微信真实业务中达到新的性能–效率前沿。

## 二、方法论

### 1. 数据构建
- **统一 pair 格式**：将所有异构任务形式化为 `zi = (I_i, q_i, c_i, N_i, y_i)`，其中 `I_i` 为任务指令，`q_i` 为源实例，`c_i` 为正例目标，`N_i` 为可选显式难负例，`y_i` 为可选分级相关性分数；`q_i` 和 `c_i` 均可包含文本、图像、视频或交错组合。
- **大规模数据覆盖**：主要包括弱监督 pair、标题 pair、检索 pair、分类 pair、多模态问答 pair、分级相关性 pair 等，覆盖多种模态、任务和领域。
- **精选数据构建**：约大规模数据 1/10 的体量，包含：
  - **语义 ID 引导重采样**：用中间检查点编码 pair，再用三层 RQ-KMeans 得到语义 ID，基于编码分配密度调整采样率，降低高频语义模式的重复暴露。
  - **质量精炼**：用多模态大模型判断 pair 是否反映正确匹配关系并过滤噪音，同时修正弱监督文本中的事实性错误。
  - **难负例构造**：文本目标由 MLLM 生成看似合理但错误的候选；图像/视频目标由模型中间检查点检索语义相似候选；部分候选再用重排模型给出相关性分数。

### 2. 模型建模
- 基于 **Qwen3.5** 原生多模态骨干，支持文本、图像、视频及任意交错输入。
- 采用 **last-token pooling**：在输入序列末尾添加专用 `<embedding>` token，取其在最后一层的隐藏状态，经 L2 归一化得到输出表示。
- 支持在序列不同位置插入多个 `<embedding>` token，例如视频后和序列末尾各放一个，可一次前向分别得到“纯视频”和“视频+文本”表示。
- 通过 **Matryoshka Representation Learning (MRL)** 支持灵活输出维度：保留隐藏状态前 `d` 维并重新归一化即可得到任意子维度嵌入。

### 3. 训练策略（两阶段）

**Stage 1：大规模多模态对齐**
- 使用 InfoNCE 对比学习，batch 内由同一数据源构成，保证任务一致、候选空间一致。
- 设计了 **duplicate-aware masking**：分别从源侧和目标侧排除近重复/语义等价样本，避免分类等任务中重复标签被误当负例。
- 对带分级标注的数据使用 **score-gap-weighted CoSENT** 排序目标，按相关性差距加权排序约束。
- 所有目标都叠加 **MRL 多维损失**：在每个支持的维度上独立计算损失后加权求和。

**Stage 2：精选微调与蒸馏**
- 继续使用对比学习和分级相关性目标，同时引入两类额外监督：
  - **Reranker 监督**：专用多模态重排模型在 query 相关候选集合上给出排序分数，转化为带分数差距权重的排序损失（`L_Rank`）；只在能稳定提升的任务上使用。
  - **嵌入蒸馏**：由更大的同族模型在线计算 batch 内源到目标、目标到源两个方向的相似度分布，用双向 KL 散度对齐师生分布（`L_Emb`），无需额外离线标注。
- 总目标为 `L_Stage2 = L_Task + λ_Emb * L_Emb`：2B / 4B 以冻结的 9B 模型为教师；9B 无更大教师，改为训练多个互补精选数据/配置的变体，再通过模型合并获得最终模型。

## 六、主要结论与发现

- **公共基准领先**：
  - MMEB-v2：2B 得分 77.9，已超过此前最强的 8B 开源基线；4B 为 79.2；9B 为 80.6，位列官方排行榜第一，超越所有已列开源与专有模型。

## 七、优点

- **性能–效率兼顾**：2B 小模型性能即可超越更大型的 8B/9B 基线，参数效率突出。
- **输入模态覆盖广**：支持文本、图像、视频、视觉文档及任意交错组合，并能通过多个 `<embedding>` token 一次前向提取不同粒度表示，工程实用性很强。
- **训练范式清晰**：两阶段“大规模对齐 + 精炼”策略，将对比学习、分级排序、重排监督和教师蒸馏有机结合，设计了重复感知掩码、语义 ID 重采样、在线相似度分布蒸馏等细节，方法创新点明确。
- **评估完整且贴近真实**：既在公共基准对标前沿模型，又有内部业务评测和在线 A/B 验证；公开了模型权重与代码，可复现性强。

## 八、不足与局限

- **模态支持不全**：当前版本不支持音频输入，在 MMEB-v3 的 11 个音频任务上全部记零分，属于明确的功能性短板。
- **算力信息缺失**：未报告训练所需的 GPU 数量、时长等，难以评估复现成本和资源门槛。
- **闭源基线可比性受限**：部分对比模型参数量未知或未公开权重，公平性只能依赖官方排行榜数据，存在一定不确定性。
- **对 MLLM 精炼的依赖**：数据质量筛选、文本修正和难负例生成大量依赖多模态大模型，可能在数据层面引入生成模型自身的偏差和错误。
- **重排监督适用范围有限**：论文承认重排候选并不在所有多模态任务上稳定有效，收益集中在少量任务子集。
- **9B 训练方案的非对称性**：9B 无更大教师，只能通过多变体合并替代蒸馏，可能限制其上限，也增加了训练流程的复杂度。
- **业务验证集中于微信生态**：内部实验和部署主要在推荐与搜索场景，跨行业

的泛化性尚未得到同等验证，结论的外部效度有待进一步检验。
- **维度与任务敏感度不均衡**：MRL 在 256 维下图像/视频任务性能保持良好，但视觉文档、检索类任务对降维较敏感，用户在实际部署时需按任务类型谨慎选择输出维度。
- **缺少针对失效案例的深入分析**：论文未系统讨论模型在哪些典型场景下仍会失败（如细粒度多模态推理、长视频时序理解等），不利于后续针对性改进。
