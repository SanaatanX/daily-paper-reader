## 摘要
文档处理流程传统上将光学字符识别（OCR）引擎与下游结构化信息提取模型串联起来，导致多阶段错误传播。我们对SmolDocling（一个紧凑的256M参数视觉语言模型，VLM）进行微调，直接从文档图像中进行端到端键值提取，在单次前向传播中联合解决识别、定位和关联问题，无需OCR预处理。我们为DocTags扩展了专门的键、值、区域和链接标签，从而在统一的输出序列中支持多对多关系。为了解决数据局限性，我们设计了一种增强流程，结合了合成表单填充和基于图的裁剪，以保留完整的键值子图。我们进一步引入了一个布局感知的评估框架，将文本匹配与空间边界框验证相结合。在FUNSD、XFUND和一个大规模私有数据集上，我们的模型在布局感知评估下优于更大的零样本VLM基线，同时比Qwen2.5-VL（7B）小27倍，推理速度快5倍以上。模型权重将在发表后公开。

## Abstract
Document processing pipelines traditionally cascade optical character recognition (OCR) engines with downstream models for structured information extraction, leading to multi-stage error propagation. We fine-tune SmolDocling, a compact 256M-parameter vision-language model (VLM), to perform end-to-end key-value extraction directly from document images, jointly solving identification, localization, and association in a single pass without OCR preprocessing. We extend DocTags with specialized key, value, region, and link tags, enabling many-to-many relationships in a unified output sequence. To address data limitations, we design an augmentation pipeline combining synthetic form filling and graph-based crops that preserve complete key-value subgraphs. We further introduce a layout-aware evaluation framework extending text matching with spatial bounding box verification. On FUNSD, XFUND, and a large-scale private dataset, our model outperforms larger zero-shot VLM baselines under layout-aware evaluation, while being 27 times smaller than Qwen2.5-VL (7B) and over 5 times faster at inference. The model weights will be released publicly after publication.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景问题**：企业超过 80% 的信息存储于非结构化文档（发票、合同、医疗表格等），而要从文档中提取结构化知识，仅靠 OCR 恢复文本远远不够。键值提取（key-value extraction）需要同时理解**文本内容**、**空间布局**和**语义关系**，即联合完成三个子任务：
  - **识别（Identify）**：判断文本元素是键（key）还是值（value）；
  - **定位（Locate）**：为每个元素预测边界框（bounding box）；
  - **关联（Link）**：建立键与值之间的有向关系，且支持多对多映射，形成有向图结构。
- **现有方法的问题**：主流系统（如 LayoutLMv3、GeoLayoutLM 等）采用**多阶段级联架构**——先用外部 OCR 提取文本和布局，再用编码器模型做 token 分类和关系提取。这种级联方式存在四个显著缺陷：
  1. **误差传播**：OCR 的错误会向下游逐级放大；
  2. **语言依赖**：OCR 的语言覆盖能力限制了可处理的语言范围；
  3. **工程复杂**：多个组件需要协调，部署和维护成本高；
  4. **输出碎片化**：产生分散的输出需要后处理才能组装成结构化键值对。
- **本文意义**：提出一种**端到端**的键值提取方案，直接处理文档图像，在单次前向传播中同时完成识别、定位和关联，无需任何外部 OCR 或布局分析组件，为文档理解提供了一种高效、紧凑的新范式。

### 2. 方法论述：核心思想、关键技术细节

#### 核心思想
- 微调 SmolDocling（一个 256M 参数的紧凑视觉语言模型），直接从文档图像生成结构化的 DocTags 标记序列，联合解决识别、定位、关联三个子任务。核心公式为：

  \[
  F : I \rightarrow \{ (k_j, v_k, B_j, B_k) : (k_j, v_k) \in R \}
  \]

  其中 I 为文档图像，\((k_j, v_k)\) 表示键值关系，\(B_j\)、\(B_k\) 为对应边界框，R 支持多对多映射，构成有向图 \(G = (K \cup V, R)\)。

#### DocTags 扩展
- 在原有 DocTags 格式上新增四个专用标签：
  - `<key_value_region>`：封装包含相关键值对的区域及其边界框；
  - `<key_i>`：标记键元素，带唯一标识符 \(i\)；
  - `<value_j>`：标记值元素，带唯一标识符 \(j\)；
  - `<link_k>`：建立从包裹元素到标识符为 \(k\) 的元素的有向链接。
- 每个键/值元素仅出现一次，多对多关系通过在键内放置多个 `<link>` 标签实现。默认采用 **link-in-key 策略**（链接放在键内）；消融实验中还探索了 link-in-value 策略及空间排序。
- 每个元素通过四个边界框 token（`<loc_x1> <loc_y1> <loc_x2> <loc_y2>`）记录位置，坐标归一化到 [0, 500] 以保持尺度不变性。

#### 模型架构
- 基于 SmolDocling / SmolVLM 架构，由两部分组成：
  - **视觉编码器**：SigLIP，patch size 16，93M 参数，处理 384×384 分辨率图像，生成 patch embedding，再经线性投影和 pixel-shuffle pooling 将序列长度缩减 4 倍；
  - **语言解码器**：SmolLM2，135M 参数，decoder-only Transformer，自回归生成 DocTags token 序列。
- 总参数量 **256M**；微调时所有参数（编码器、投影器、解码器）均不冻结。

#### 训练目标
- 标准交叉熵损失，条件为视觉 token。
- 探索了 **token 感知加权损失**：对结构化标签（`<key_value_region>`、`<key>`、`<value>`、`<link>`）设置权重 \(\lambda=5\)，防止高频内容 token 主导损失。

#### 数据增强管道
1. **合成表单填充**：DocLayNetV2 中存在大量空表单字段，导致模型学到预测空值。使用 Qwen2.5-VL 72B 根据文档图片和键文本生成上下文合适的值，再以自适应字体大小和多行换行渲染到空白区域，并更新边界框标注；
2. **基于图的裁剪增强**：构建键值对图 → 计算连通分量 → 合并空间邻近分量 → 添加随机 padding 生成聚焦裁剪，保留完整的键值子图不碎裂；
3. **图像变换**：使用 Albumentations 实现腐蚀/膨胀、高斯噪声、高斯模糊、颜色抖动、位图阈值化、JPEG 压缩伪影等在线增强，且保证边界框有效。

#### 布局感知评估框架
- 传统评估仅做文本匹配（SER 和 RE），对端到端模型不充分——一个预测文本正确但定位偏移 200 像素的结果仍会被判对。
- 本文引入**布局感知匹配**：实体判为真正例需同时满足：
  1. 文本匹配（Levenshtein 相似度 \(\rho_{Lev} \ge 0.8\)）；
  2. 语义标签一致（key/value）；
  3. 空间重叠满足 \(IoU(B_p, B_g) \ge 0.7\)。
- 关系判为正确需源键和值均满足上述三个条件。采用**匈牙利算法**进行全局最优二分匹配（最小化负 IoU），避免重复计数并处理同文本多位置的情况。

### 6. 主要结论与发现

1. **紧凑模型可超越大规模零样本 VLM**：256M 参数的 SmolDocling 在布局感知评估下全面超越 7B 的 Qwen2.5-VL（FUNSD SER 0.514 vs 0.273、RE 0.275 vs 0.144；XFUND SER 0.412 vs 0.285、RE 0.206 vs 0.123），比其小 **27×**，推理速度快 **>5×**（0.27s/sample vs 1.40s/sample）。
2. **数据管道比模型规模更重要**：任务特定的微调加上精心设计的增强管道（合成填充 + 图裁剪），比单纯扩大模型规模更能提升 OCR-free 场景下的表现。
3. **数据管道各组件贡献不均**：裁剪增强和合成表单填充带来最大增益（RE 提升最高达 41%）；图像变换在噪声文档（FUNSD）上有益，在干净 PDF（DocLayNetV2）上轻微负收益。
4. **布局感知评估更严格**：加入 IoU≥0.7 空间验证会使分数显著下降（如本文模型在 FUNSD 从 0.679/0.376 降至 0.514/0.275），但趋势保持不变，说明空间正确性确是端到端模型的关键挑战。
5. **链接策略存在权衡**：空间排序提升 SER 但略降 RE；link-in-key 在关系提取上最稳定，成为主配置的选择依据。

### 7. 优点：方法与实验设计亮点

- **端到端架构创新**：完全摆脱 OCR 依赖，单次前向传播同时完成识别、定位、关联，消除级联误差传播，简化工程部署。
- **DocTags 扩展设计精巧**：四个专用标签配合唯一标识符和 `<link>` 机制，在统一输出序列中自然表达多对多关系，无需任务特定的后处理；边界框 token 提供空间定位，支持下游视觉检索和重复字段消歧。
- **数据增强管道富有实用性**：合成表单填充利用大模型生成语义合理的值，解决空字段问题；基于图连通分量的裁剪确保语义单位的完整性，大幅提升关系提取效果。
- **评估框架更具真实性**：布局感知匹配（文本 + 标签 + IoU≥0.7）配合匈牙利最优匹配，避免了传统纯文本评估对空间错误的忽视，为端到端文档模型提供了更合理的评测标准。
- **效率优势显著**：256M 参数适合端到端部署场景，具备在本地设备上运行（on-device deployment）的潜力，兼顾隐私与延迟约束。

### 8. 不足与局限

- **与 OCR/布局编码器模型仍有差距**：本文模型尚未达到接收预提取文本和布局的编码器模型（如 LayoutXLM）的绝对性能，尽管这种比较在输入假设上不对称；
